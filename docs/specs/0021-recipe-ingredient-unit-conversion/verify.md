## UI / manual

- [x] Open a recipe detail page (web) whose ingredients include at least one parseable amount → an oz / ml / cl toggle appears above the ingredient list → AC-1 — web confirmed via Playwright against `http://localhost:3000/en/recipes/acid-4b93d84f-8cbb-44a9-a1de-b6605a5c4f4a` (the "ACID" recipe); mobile not exercised, no simulator/device available in this environment
- [x] With the toggle showing, switch to ml → every convertible ingredient's displayed amount updates on the page → AC-1 — driven click, "Wild Turkey" line went from "1 oz" to "29.6 ml"
- [x] With ml selected, check a converted line (e.g. an ingredient parsed as "1 1/2 oz") → shows as a decimal rounded to the nearest tenth with a trailing "ml" (e.g. "44.4 ml") → AC-2 — "1 oz" → "29.6 ml" (29.5735 rounded to the nearest tenth), screenshot `02-after-ml.png`
- [x] Switch to cl → the same line shows a decimal rounded to the nearest tenth with a trailing "cl" (e.g. "4.4 cl") → AC-2 — "29.6 ml" → "3 cl" (2.95735 rounds to 3.0, trailing .0 trimmed), screenshot `03-after-cl.png`
- [x] Switch back to oz → the line returns to its original parsed form (fraction or decimal, e.g. "1 1/2"), never shown as a decimal while oz is selected → AC-2 — returned to exactly "1 oz" (verbatim `measure` text, not re-derived)
- [x] Find a recipe with an unparseable line (a non volume unit like "2 Dashes", or a vague phrase like "a splash") → that line's text never changes as the toggle is switched between oz/ml/cl → AC-3 — the "151 proof rum" line ("1 oz Bacardi") stayed byte identical across all four toggle clicks
- [x] Load any recipe detail page fresh (first visit, or revisiting a page seen before) → the toggle always starts on oz, never remembers a prior selection → AC-4 — SSR HTML on fresh load shows `aria-pressed="true"` on the oz button
- [x] Open the same recipe detail page in the Spanish locale → the unit toggle still appears and functions, and toggling shows the same converted numbers as the English view; only the unit word (oz/ml/cl) differs by locale, never the number → AC-7 — Spanish page, clicked ml, same "29.6 ml Wild Turkey" as English; nav chrome translated, unit word and number unchanged, screenshot `04-es-after-ml.png`
- [x] Open a recipe whose ingredients are all unparseable (e.g. entirely "to taste"/dashes) → no toggle renders at all → AC-1, AC-3 (Toggle visibility row) — the "Avalon" recipe (5 ingredient lines, all `amountValue`/`amountUnit` null) rendered zero occurrences of the toggle group
